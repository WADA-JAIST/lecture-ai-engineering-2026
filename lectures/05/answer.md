- 取り組んだレベル：基礎
- やったこと（変更したファイル・設定・処理、または設計した取得方法）：`app/config.py`の`RAG_TOP_K`を5から1に変更し、通常検索で返す最大ページ数を減らした。索引は再作成していない。
- 比較した質問と、固定した条件（モデル・対象資料など）：演習と同じ「第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？」を、同じ`gemini-3.5-flash-lite`と第1〜3回の資料で各1回実行。どちらも`uv run python -m app.agent --trace "$AIE_QUESTION"`を使用。
- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：変更前（`RAG_TOP_K=5`）は`search_materials`を1回呼び、検索引数は`LoRA QLoRA 固定 学習 第2回`、回答はPDF p.52とp.51を根拠にした。3.41秒、入力3,037／出力208トークン、モデル応答2回、推定費用$0.001431。変更後（`RAG_TOP_K=1`）も1回呼び、検索引数は`LoRA 固定 学習 QLoRA 加える`、PDF p.52のみを根拠に同じ要点を回答した。2.19秒、入力1,191／出力150トークン、モデル応答2回、推定費用$0.000732。
- 改善した例と、残る失敗・制約：この質問では1ページに必要な根拠がそろい、回答内容を保ったまま入力トークン数と推定費用が減った。ただし各条件1回の測定で、検索語もモデルが生成するため、時間・費用の差が`RAG_TOP_K`だけによるとは断定できない。複数ページの根拠が必要な質問では、件数を減らすと必要なページを取り逃がす可能性がある。
- 気づき・疑問：質問の答えが1ページにまとまっている場合、検索件数を増やすより必要な根拠を絞るほうが効率的だった。質問の種類ごとに適切な件数は変わりそう。
